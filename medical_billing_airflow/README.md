# Medical Billing — local Airflow 3

## Prerequisite
Docker Desktop running. Port 8080 free on Windows. Airbyte remains on port 8000.

For first-time setup, copy [`.env.example`](.env.example) to `.env` in this directory. If `.env` already exists, add the new setting to it.

- Set `DBT_IMAGE` to the dbt runner image available to your Docker daemon.
- Set `AIRBYTE_CONNECTION_ID` to the UUID of the PostgreSQL-to-SQL Server sync in Airbyte. Compose requires this value and passes it to the DAG.

Create the `airbyte_default` connection in Airflow with the API endpoint and authentication for your Airbyte installation. That connection tells Airflow how to reach the API. The UUID selects the sync to run.

## Start (PowerShell)
Open PowerShell in the folder containing `docker-compose.yml`:

```powershell
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs -f airflow
```

The initial `standalone` startup initializes the metadata DB and creates a login. Look in the container startup logs for credentials. If an autogenerated password is saved in a container-side file, inspect it through `docker exec` without uploading it anywhere. Open http://localhost:8080.

After changing the UUID, run `docker compose config --quiet` and `docker compose up -d` to apply the new environment. In Airflow, confirm that `medical_billing_ingestion` loads without import errors, then trigger it and check that `sync_postgres_to_sqlserver` succeeds.

## Stop / restart

```powershell
docker compose stop
docker compose start
```

Do not run `docker compose down -v` unless you want to delete the persistent Airflow metadata volume.

## DAGs
Put Python DAG files in `./dags/`. They appear in the Airflow UI after parsing.

## Local-development notes
- Uses Airflow 3.3.1 in `standalone` mode and SQLite metadata storage, intended for learning/development, not production.
- Does not reuse uploaded stale `airflow.db`, PID files, `airflow.cfg`, or passwords.
- The SQLite metadata lives in the Docker named volume `airflow_data`.
- This Compose project is isolated from Airbyte, PostgreSQL, and SQL Server; no extra published DB ports.
- If Docker resources are constrained, stop unused services while configuring Airflow.
